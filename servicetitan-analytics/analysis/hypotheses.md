# Backlog гипотез: почему падает выручка

Каждая гипотеза: **индикатор** (метрика из ServiceTitan) → **ожидаемый паттерн,
если верна** → **тест/эксперимент** → срок/ответственный. Заполняется по мере
прохождения Этапов 1–3. Сначала смотрим, какой фактор воронки (`L·b·r·c·t`) дал
наибольший отрицательный вклад в `revenue_decomposition` — он сужает список.

## Спрос (фактор L)

| # | Гипотеза | Индикатор | Если верна | Тест |
|---|---|---|---|---|
| H1 | Упали лиды: срезали маркетинг / просел канал | call leads по campaign YoY, расход по каналам | падение L при стабильных b,r,c,t; конкретный канал просел | вернуть/перераспределить бюджет на рабочий канал, замерить лиды |
| H2 | Сместилось качество лидов | доля price_shopping/spam в `call_analysis`, booking rate по источнику | L стабилен, но booking rate ниже у новых источников | отключить/оптимизировать слабый источник |
| H3 | Погода/сезон (мягкий год → меньше поломок) | YoY по emergency/service джобам, внешние данные | падение во всех caller-сегментах равномерно, отрасль тоже | внешнее — не чинится, но объясняет часть Δ |
| H4 | Конкурент/демпинг | доля not_booked_reason='price', win-rate по эстимейтам | рост price-возражений, падение conversion | конкурентный анализ цен, оффер/пакеты |

## Конверсия (факторы b, c, t)

| # | Гипотеза | Индикатор | Если верна | Тест |
|---|---|---|---|---|
| H5 | Booking rate упал: текучка/необученные CSR, пропущенные звонки | `agg_by_csr` booking rate, answer rate, missed-opp rate | booking ниже у конкретных CSR / в вечерние часы | A/B на скриптах, обучение, добавить смену/автоответ |
| H6 | Конверсия техников упала: слабый апселл, «только диагностика» | conversion rate по технику, средний чек по технику | c ниже у части техников | коучинг, ревью эстимейтов, бонус за конверсию |
| H7 | Средний чек упал: микс в дешёвый ремонт, скидки, не подняли цены | average ticket, доля install vs service, скидки | t падает, микс сместился к service | поднять прайс, продвигать замены/пакеты |
| H8 | Рост отмен/no-show (диспетчеризация) | cancellation/no-show rate, run rate r | r падает при стабильном b | напоминания, подтверждения, оптимизация расписания |

## Ёмкость (факторы r, рекуррентка)

| # | Гипотеза | Индикатор | Если верна | Тест |
|---|---|---|---|---|
| H9 | Меньше техников → не успевают отрабатывать спрос | tech-часы, utilization, доля непринятых/перенесённых | спрос (L) есть, но completed ниже из-за ёмкости | найм, перераспределение, аутсорс пиков |
| H10 | Сжимается база мембершипов → меньше рекуррентки и повторных | active memberships, renewal rate YoY | падение recurring + повторных обращений | кампания продления, продажа мембершипов на джобах |

## Журнал проверок

> По мере тестирования: дата, гипотеза, что нашли в данных, вердикт
> (подтверждена / отклонена / частично), эффект, следующий шаг.
